# 安全体系设计

## 1. 信任域与多租户隔离

系统分为平台授权域、客户主控域和边缘数据面。授权域使用独立身份、数据库、签名密钥和审计；租户数据只能由客户主控按 `tenant_id` 访问；Agent 只接收经过授权的不可变制品和命令引用。

PostgreSQL 表统一带租户归属或平台作用域，应用事务设置不可伪造的租户上下文，关键表使用 Row-Level Security 作为第二道防线。所有查询、缓存键、NATS subject、ClickHouse 分区键和对象存储路径都包含规范化租户标识。跨租户导出、代登录和平台支持采用显式授权、短时会话和双边审计。

## 2. RBAC 与高风险操作

权限采用 `resource.action`，角色支持系统预置和租户自定义。默认拒绝；删除、发布、回滚、账务调账、密钥轮换和管理员代登录需要额外权限、幂等键、版本条件和审计。权限变更不会自动扩展已有自定义角色，必须显式迁移并验证。

策略决策输入包括主体、租户、资源、动作、资源状态、会话新鲜度和授权租约。拒绝返回稳定原因码。审计事件记录前后字段摘要和策略版本，不记录凭据、令牌、私钥或原始请求体。

## 3. API 安全

外部 API 仅提供 HTTPS、版本化 OpenAPI 和稳定错误码。默认启用 CORS 同源策略、CSRF 防护（Cookie 请求需校验 Origin/CSRF token）、请求体/分页/批量大小限制、内容类型白名单和严格超时。写操作要求 `Idempotency-Key`，并以租户、主体和请求摘要绑定；并发修改要求 `If-Match`/revision。

服务端统一验证路径参数、URL、CIDR、证书 SAN、DNS 记录和上传制品。外部 provider 调用禁止跟随重定向、限制响应大小并使用出站 allowlist；日志采用字段白名单。Prometheus、健康检查和管理端点不暴露业务秘密。

## 4. Agent 认证与通信加密

Agent 注册使用一次性 token、CSR、机器指纹和能力协商；token 数据库只保存哈希并原子消费。日常使用 TLS 1.3 mTLS、短期客户端证书和精确 URI SAN 节点身份。生产根 CA 离线保存，中间 CA 使用 KMS/HSM 兼容签名器；开发环境使用隔离 CA。

Gateway 与 control-api 通过独立的内部 mTLS 和固定 workload URI SAN 通信。NATS 使用按 subject 限制的账号，Redis 使用认证和网络隔离。边缘请求路径不依赖这些控制面组件；控制面不可用时 Agent 继续守护最近健康版本。

## 5. 密钥管理

密码使用 Argon2id；refresh token、enrollment token 和 API key 只存哈希。DNS、支付、通知和插件凭据采用信封加密：KMS/HSM 管理 KEK，应用使用随机 DEK 加密并保存 key ID、nonce、ciphertext 和版本。私钥、数据库口令、签名材料和 Webhook secret 通过 Secret Manager/只读挂载注入，禁止进入 Git、镜像层、日志和审计。

密钥轮换支持双读单写、版本标识、最短有效期和回滚窗口。签名公钥以固定 trust pin 引导，租约/策略必须验证签名链、单调修订、目标和有效期；未知 key、过期或回放保留最近有效值并告警。

## 6. 审计与检测

审计流仅追加，字段包括 actor、授权主体、租户、动作、资源、结果、来源、request/trace/task ID、时间、previous hash 和 event hash。应用角色禁止 UPDATE/DELETE；定期签名检查点写入异机安全域。资金、权限、节点身份、配置发布/回滚、凭据和人工豁免必须审计，审计写失败时高风险事务失败关闭。

安全监控覆盖认证失败、Token 重放、跨租户拒绝、证书异常、密钥轮换、权限漂移、异常部署、Gateway 接管、NATS DLQ、审计链断裂和 provider 出站失败。告警包含稳定原因码、影响范围和回滚/隔离动作。

## 7. 验收边界

安全验收必须包含跨租户访问、越权 API、CSRF、IDOR、重放、限流、秘密泄露扫描、证书撤销/轮换、Redis/NATS 故障、审计篡改检测、备份恢复和边缘断控运行。渗透测试结果与功能测试分开记录，不能用静态代码扫描代替真实协议和部署验证。

## 8. 安全控制矩阵

| 风险 | 预防控制 | 检测证据 | 恢复方式 |
| --- | --- | --- | --- |
| 跨租户读取/写入 | 服务端 scope、RLS、复合外键、缓存键隔离 | 403/404、拒绝审计、IDOR 测试 | 撤销会话并检查受影响资源 |
| Token/refresh 重放 | 短寿命、轮换、family revision、撤销版本 | `refresh_replay` 事件和会话状态 | 撤销整条 family，要求重新登录 |
| Agent 私钥泄露 | mTLS、短证书、最小权限、私钥不进控制面 | 证书序列、SAN、节点接管告警 | 吊销节点、签发新证书、保留当前边缘版本 |
| 配置/制品篡改 | 签名、SHA-256、不可变版本、原子切换 | manifest、签名校验、部署状态 | 回滚到最近 healthy 版本 |
| 审计被改写 | 仅追加、哈希链、异机检查点 | 定期链校验和 checkpoint 对账 | 隔离审计副本并停止高风险写入 |
| provider/插件被利用 | 出站 allowlist、响应上限、进程外 Webhook、权限默认拒绝 | 出站日志、调用码、超时/DLQ 指标 | 禁用 integration 或插件，重放安全事件 |

## 9. 安全默认值与边界

默认拒绝 CORS、默认关闭调试端点、默认禁止危险上传类型、默认限制批量和导出大小。安全开关必须有稳定配置版本和审计，不能通过前端隐藏按钮替代服务端拒绝。任何“兼容旧行为”的开关都必须有过期时间、负责人和移除条件。

数据库超级用户、KMS/HSM 管理员和宿主机 root 能力属于系统外部信任边界；设计只能通过权限分离、双人操作、备份加密和异机审计降低风险，不能声称应用层哈希链可以防止拥有全部基础设施权限的攻击者。

## 10. 安全验收门槛

每个新增接口至少提供成功、无效输入、认证失败、权限拒绝、跨租户、重放、并发和依赖不可用用例。每个高风险操作同时提供审计断言、幂等断言和回滚断言。发布前必须通过秘密扫描、依赖漏洞策略、容器非 root 检查、TLS 配置检查、SBOM 生成和真实浏览器拒绝路径。
