# ADR-0002：国际化、开放扩展与平台策略分发

- 状态：已接受
- 日期：2026-07-22
- 关联文档：[平台架构](../architecture.md)、[授权中心架构](../licensing/architecture.md)

## 背景

平台必须默认向用户和运营人员提供完整中文界面，同时保留增加其他语言的能力；还必须交付可用于第三方开发和未来插件市场的稳定文档与契约。平台授权中心需要向全部客户主控或指定主控实例下发最新平台策略，但不能突破授权中心、客户主控和边缘数据面的信任边界。

## 决策

### 用户语言与错误

- `apps/web` 和 `apps/operator-console` 使用 i18next/react-i18next，按应用与领域拆分命名空间；`zh-CN` 是默认、必备且完整的 locale。
- 页面标题、导航、表格、表单、校验、状态、日期、数字、货币和相对时间均从语言资源或 locale-aware formatter 生成。业务组件不得内嵌用户可见文案。
- API 返回稳定错误码、字段和插值参数，不返回供 UI 直接展示的英文异常。前端负责本地化；未知错误使用中文安全兜底并保留 request ID。
- CI 检查语言键缺失、未使用键和默认语言完整性，并用文本膨胀的伪 locale 做桌面及移动端浏览器验收。

### 文档与插件扩展契约

- OpenAPI、protobuf 和事件 schema 是机器可读契约源；生成的 API 参考、示例请求、错误码和兼容说明必须与代码在同一变更中更新并由 CI 检查漂移。
- 系统文档分为用户手册、运维手册、API 参考和开发者对接指南。开发者指南覆盖认证、作用域、租户边界、分页、幂等、限流、错误、Webhook 验签、重试、事件顺序、版本弃用和完整示例。
- 插件以版本化 manifest 声明标识、版本、兼容范围、所需作用域、订阅事件、Webhook 和配置 schema。安装时明确授权，升级新增权限必须再次批准，禁用或卸载立即撤销凭据和事件投递。
- 首期扩展只通过进程外 OpenAPI、Webhook 和持久事件工作；第三方不得直接访问数据库，也不得把任意代码加载到 `control-api`、`license-service`、Gateway 或 Edge Agent 进程。若未来需要托管运行时，必须另立 ADR 并证明沙箱、资源限制、供应链签名和故障隔离。

### 平台策略分发

- `license-service` 管理只追加的策略修订。每个策略包含稳定 schema、目标选择器（全部实例或明确 installation ID 集合）、优先级、发布时间、有效窗、最低/最高兼容版本、规范 payload、摘要、签名 key ID 和签名。
- 全局策略和实例策略分别保持单调 revision；同一策略域内实例策略优先于全局策略。撤回和回滚通过新的签名修订表达，不删除或覆盖历史记录。
- 客户主控使用安装身份拉取候选策略，通过 ETag/游标增量同步，验证签名、目标、时间、schema 和版本兼容后原子保存为最近有效策略，再由本地领域适配器应用。授权中心不连接客户数据库，也不投递可执行代码或任意 SQL。
- 主控回报 `fetched/validated/applied/rejected/rolled_back` 状态、策略 revision、摘要、错误码和时间。授权中心展示覆盖率和差异，但回执不作为签发事实的唯一副本。
- 无效签名、未知 schema、过期、乱序或不兼容策略必须拒绝并保留最近有效策略。授权中心离线不影响已激活边缘流量；策略不得进入每个 HTTP/TCP 请求的同步依赖链。
- 发布支持预检、指定实例金丝雀、暂停、扩批和用新修订回滚。会直接中断边缘流量、泄露客户数据或绕过客户审计的策略类型永久禁止。

## 结果

该决策增加语言资源、文档漂移检查、扩展契约和策略同步状态机的工程成本，但为中文完整性、未来国际化、插件生态和跨安装运营建立了可验证边界。它不引入额外微服务，也不允许授权中心成为客户主控的远程超级管理员。

## 验收

- 两个 Web 应用在 `zh-CN` 下无可见英文和缺失键；伪 locale 的桌面/移动截图无溢出。
- 契约生成与文档示例在 CI 中可执行，隔离示例插件覆盖最小权限、幂等、Webhook 验签、重试、撤销和租户隔离。
- 策略端到端测试覆盖全局/指定目标、优先级、重复、乱序、篡改、过期、未知 schema、版本不兼容、离线缓存、灰度暂停与回滚，并证明边缘流量在授权中心不可用时继续。
