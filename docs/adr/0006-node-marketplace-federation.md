# ADR 0006：节点市场、订阅制与无限代理

- 状态：用户已确认方向（2026-10-14），设计阶段；未实现、未部署。
- 日期：2026-10-14
- 详细设计：[docs/marketplace/](../marketplace/README.md)

## 背景

传统授权模式是“用户买授权、自建主控和节点、自己找客户”。各主控彼此孤立，节点资源无法流通。我们在保留这种模式的同时，要让所有授权主控把自己的节点挂到平台市场上，供其他主控付费订阅，订阅来的资源还可以和自有节点组合后再卖，层级不设上限。

## 用户已确认的决策

1. 配置下发：订阅成立时，供给方主控自动开一个受限用户，按订阅规格设好额度；订阅方主控凭市场签发的凭证调用供给 API 下发站点。接受“供给方能看到订阅方客户的域名和流量”。
2. 资金：平台只做撮合和记账，不代收代付。买卖双方之间用余额预充值，平台按记账结果控制服务状态。
3. 无限代理：每一级都可以把自有节点和订阅来的节点组合起来再卖，层级不设上限。
4. 授权模式保留“买授权自建”式购买：参与市场必须先持有授权（授权端可设套餐、免费模式）。平台是否抽成、抽多少，以及业务形态和促销政策，都由授权端管理员随时调整。
5. 计费最小单位为天。支持按天包资源、按流量、95 带宽计费等多种形式。
6. 备案：由节点提供者自行勾选哪些供给或节点必须做备案校验。勾选后，未备案的域名无法使用；订阅方在市场上能看到该标记。

## 设计决策（由本 ADR 确定）

- **统一“供给”抽象**：站点由一组供给承载。供给可以是自有节点组、市场订阅或第三方 CDN；调度层统一按地区、线路和拨测结果选择。
- **流量不走代理链，只有账走代理链**：访客直接到达物理节点。转售链只存在于订单和结算中；配置直接落到最终提供节点的主控（叶子供给方）。
- **市场独立部署**：新建 `market-service`，部署在独立主机、使用独立数据库，不并入 `license-service`，保持授权签发的安全边界不变。市场只读取授权端的安装身份和授权功能项。
- **权威 DNS 托管在外部的多家 DNS 服务商**：由使用者从预接入列表中选择，列表注明是否支持国内三网分线路。市场写入记录；市场宕机时，记录保持最后一次同步的状态继续应答。
- **部署**：新增 1 台市场主机，授权端 68 不变；DNS 和拨测都不自建机器。
- **拨测**：首期卖家节点互测，后续接入拨测站 API。
- **备案查询**：平台预接入几家，卖家自选、自己填 Key、自己付费。
- **抽成**：在授权端账单向卖家收取；规则（基数、点位）由管理员按计费方式设置。
- **主控只出站连接市场**：供给方主控不需要开放入站端口。供给 API 经市场中继通道送达，载荷做端到端加密，市场只能看到用于合规校验的元数据。
- **第三方 CDN 只能作为成员私有供给**：必须使用成员自己的账号，不能上架市场转售。
- **证书默认不外发私钥**：每个供给方自己签发证书。通过把 `_acme-challenge` 委派给市场的 ACME DNS，多个供给方可以同时签发；上传私钥属于显式选择，并会明示提示。

## 后果

- 正面：节点资源可以在全网流通，形成网络效应；单机授权体验不受影响；市场故障不影响已上线的流量。
- 代价：新增一个独立服务和一台主机；需要外部 DNS 和拨测点的成本；计量依赖供给方上报，只能做到“可追责”，无法做到“不可伪造”；主控之间存在版本差，需要做协议版本协商。
- 风险：内容合规与滥用（由备案校验、实名、接入规则、举报下架、黑名单兜底），以及资金合规（不代收代付，平台抽成走授权端自己的账单）。

## 被否决的方案

- 授权端直接中转配置到节点：授权端会成为所有流量配置的中心，供给方失去对自己节点的控制。
- 订阅方主控直连供给方节点：节点需要同时信任两个控制面，安全模型不成立。
- 订阅方主控直连供给方主控的公网 API：要求每个供给方暴露入站端口和主控 IP，攻击面过大。语义保留，传输方式改为市场中继。
